# AGENTS.md

Guide for contributors and AI agents working on **Boxier**.

## Project overview

Boxier is a universal sandbox mod for Minecraft, built with NeoForge.

## Language rules

- All code, identifiers, comments, commit messages and user-facing strings
  MUST be written in English.
- Keep commit messages short and follow Conventional Commits
  (`feat: ...`, `fix: ...`, `refactor: ...`, `chore: ...`).

## Code style

- Match the style of the surrounding code (formatting, naming and imports).
- Keep methods small and focused on a single responsibility, and prefer clear,
  readable code over clever code.
- Use descriptive names for classes, methods, fields and local variables.
- Do not add comments unless they explain non-obvious behavior. Prefer letting
  the code speak for itself.
- Remove dead code, commented-out code and unused imports before committing.
- Reuse the versions and properties already declared in `gradle.properties`
  instead of hardcoding them.
- Run `./gradlew build` before opening a pull request.

## Committing and pushing

- Use short, imperative commit messages in English with a Conventional Commits
  prefix:
  - `feat: short message` - a new feature.
  - `fix: short message` - a bug fix.
  - `refactor: short message` - a change that neither adds a feature nor fixes a
    bug.
- Never add AI authorship or co-author trailers (no `Co-Authored-By`, no
  "Generated by ...", no tool/agent attribution). The commit author is the human
  contributor only.
- Stage only the intended files, then commit and push to the current branch.

```bash
git add <files>
git commit -m "feat: short message"
git push
```

## Releasing

Releases are cut through the **manual** `Release` GitHub Action
(`.github/workflows/release.yml`, `workflow_dispatch`). It bumps `mod_version`
in `gradle.properties`, generates release notes from the Conventional Commits
since the last tag (with commit references), commits `chore(release): v<version>`,
pushes a `v<version>` tag, and creates a GitHub Release.

To bump the version locally:

```bash
bash scripts/bump-version.sh <bump> [preid] [version]
```

To generate release notes locally:

```bash
bash scripts/release-notes.sh
```

### Building the mod

The **Build** GitHub Action (`.github/workflows/build.yml`) builds the mod jar
with Gradle, uploads it as a workflow artifact, and attaches it to the release.
It runs automatically after a release, and can also be dispatched manually with
a tag (e.g. `v0.0.1`).

Locally, run `./gradlew build`; the mod jar is written to `build/libs/`.
